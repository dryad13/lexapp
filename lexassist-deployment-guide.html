lexassist.uk/portal — How to get there

GoDaddy gives you a domain name. It does not give you a server to run Node.js apps. Here's the architecture that makes lexassist.uk/portal work, entirely free.

User visits
lexassist.uk/portal
→
Cloudflare
free — routes /portal/*
→
Railway / Render
free — runs Node.js + Postgres

The key insight: GoDaddy only needs to point your domain's nameservers at Cloudflare. Cloudflare then handles everything — SSL, routing, and forwarding /portal traffic to wherever your app is actually running (Railway, Render, a VPS, anything).

ℹ
Why Cloudflare? GoDaddy shared hosting cannot run Node.js or PostgreSQL. Cloudflare's free tier acts as a smart proxy — it intercepts requests to lexassist.uk/portal/* and silently forwards them to your Railway/Render app. The visitor never sees the Railway URL.
✅ What you'll have
• lexassist.uk — can still be your GoDaddy website / landing page
• lexassist.uk/portal — the full LexAssist app
• Free SSL on both
• No server to manage
📋 What you need
• Free Cloudflare account
• Free Railway or Render account
• Free GitHub account
• ~30 minutes total

The four steps

1
Code changes — tell the app it lives at /portal
Two small changes: Vite base path and wouter router base. Without this the app's internal links break under a subpath.
2
Deploy the app to Railway (or Render)
Push to GitHub, connect to Railway, add Postgres and env vars. Takes ~10 minutes. Railway gives you a URL like lexassist.up.railway.app.
3
Set up Cloudflare — point your domain at it, create Worker
Add lexassist.uk to Cloudflare (free). Create a Worker that proxies /portal/* to your Railway app.
4
Update GoDaddy nameservers
Replace GoDaddy's nameservers with Cloudflare's two nameservers. Takes 5 minutes + up to 24 hours DNS propagation.

Step 1 — Code changes for /portal

The app currently assumes it lives at /. Two files need updating so internal links, assets, and routing all work under /portal.

⚠
These are the only two code changes needed. Everything else (colours, branding, logic) stays exactly as it is. Make these changes before building and deploying.

Change 1 — vite.config.ts — add base path

This tells Vite to prefix all built asset URLs with /portal. Without it, the built HTML will reference /assets/index.js instead of /portal/assets/index.js and the page will be blank.

// vite.config.ts — add the base field
export default defineConfig({
  base: "/portal/",   // ← ADD THIS LINE
  plugins: [
    react(),
    runtimeErrorOverlay(),
    ...
  ],
  resolve: { ... },
  root: path.resolve(import.meta.dirname, "client"),
  build: {
    outDir: path.resolve(import.meta.dirname, "dist/public"),
    emptyOutDir: true,
  },
});

Change 2 — client/src/App.tsx — add wouter base

Wouter (the router) needs to know the base path so that /portal/dashboard matches the /dashboard route. Add the Router import and wrap the app in it.

// App.tsx — add Router import and wrap AppContent
import { Switch, Route, useLocation, Router } from "wouter";

// ... (rest of file unchanged until the App() function at the bottom)

function App() {
  return (
    <Router base="/portal">
      <QueryClientProvider client={queryClient}>
        <ThemeProvider>
          <AuthProvider>
            <AppContent />
            <Toaster />
          </AuthProvider>
        </ThemeProvider>
      </QueryClientProvider>
    </Router>
  );
}

Change 3 — client/src/main.tsx — fix service worker path

The service worker registration currently hardcodes /sw.js. Update it to /portal/sw.js.

// client/src/main.tsx
if ("serviceWorker" in navigator) {
  window.addEventListener("load", () => {
    navigator.serviceWorker.register("/portal/sw.js").catch(() => {});
  });
}
ℹ
That's all the code. After making these three changes, run npm run build locally to confirm it compiles without errors before deploying.

Step 2 — Deploy the app to Railway

Railway is free to start (5$ credit, no card needed for the trial). It gives you Node.js hosting + PostgreSQL. The whole setup takes about 10 minutes.

1
Push your code to a GitHub repo
Unzip the project, make the code changes from Step 1, then:
cd lexassist_themed_full/lexassist
git init && git add .
git commit -m "LexAssist — portal subpath"
# Create a new repo at github.com first, then:
git remote add origin https://github.com/YOURNAME/lexassist.git
git push -u origin main
2
Create a Railway project
Go to railway.app → Sign up → New Project → Deploy from GitHub Repo → select your repo. Railway detects Node.js automatically.
3
Add a PostgreSQL database
In your project click + New → Database → PostgreSQL. Railway automatically adds DATABASE_URL to your service's environment.
4
Add environment variables
In your service → Variables tab:
SESSION_SECRET  = any-long-random-string-minimum-32-chars
ENCRYPTION_KEY  = f34f9c8b882826c7dc99de0aabd94fa2461bace802f009657b5916c32095d89c
OPENAI_API_KEY  = sk-your-key   # optional
NODE_ENV        = production
PORT            = 5000
5
Set build and start commands
In your service → Settings: Build Command = npm run build · Start Command = npm start. Click Deploy.
6
Push the database schema (once)
Once the deploy is live, open Railway's terminal for your service:
npm run db:push
7
Note your Railway URL
Railway gives you a URL like lexassist-production.up.railway.app. Copy this — you'll need it in Step 3.
ℹ
Test it first. Before setting up Cloudflare, visit https://your-app.up.railway.app/portal/ — you should see the LexAssist landing page. If it's blank, the base path code changes in Step 1 may be missing.

Step 3 — Cloudflare setup

Cloudflare routes lexassist.uk/portal/* traffic to your Railway app. This is entirely free.

3a — Add lexassist.uk to Cloudflare

1
Create a free Cloudflare account
Go to cloudflare.com → Sign up for free → Add a site → enter lexassist.uk → choose the Free plan.
2
Cloudflare scans your DNS
Cloudflare automatically imports your existing GoDaddy DNS records. Review them and click Continue. Cloudflare will give you two nameservers — keep that page open, you'll use them in Step 4.
3
Add a placeholder DNS A record
In Cloudflare DNS, add an A record so the domain resolves (Cloudflare Workers don't need a real server behind them, but the zone needs at least one record):
Type:    A
Name:    @              # this means lexassist.uk
Value:   192.0.2.1      # a dummy IP — the Worker intercepts before it's used
Proxy:   Proxied (orange cloud ON)

3b — Create the Cloudflare Worker (the proxy)

4
Go to Workers & Pages
In your Cloudflare dashboard left sidebar → Workers & Pages → Create → Create Worker. Name it lexassist-portal.
5
Paste this Worker code
Click Edit Code and replace the entire default script with this. Change the URL to your actual Railway app URL:
// Cloudflare Worker — proxies lexassist.uk/portal/* to Railway
const UPSTREAM = "https://YOUR-APP.up.railway.app"; // ← your Railway URL

export default {
  async fetch(request) {
    const url = new URL(request.url);

    // Only proxy requests that start with /portal
    if (!url.pathname.startsWith("/portal")) {
      return new Response("Not found", { status: 404 });
    }

    // Build the upstream URL — keep the full path
    const upstreamUrl = new URL(url.pathname + url.search, UPSTREAM);

    // Forward the request, preserving method, headers, body
    const upstreamReq = new Request(upstreamUrl.toString(), {
      method:  request.method,
      headers: request.headers,
      body:    request.method !== "GET" && request.method !== "HEAD"
                 ? request.body
                 : null,
      redirect: "follow",
    });

    const response = await fetch(upstreamReq);

    // Return the response as-is
    return new Response(response.body, {
      status:     response.status,
      statusText: response.statusText,
      headers:    response.headers,
    });
  },
};
6
Deploy the Worker
Click Deploy. The worker is now live at lexassist-portal.YOUR-SUBDOMAIN.workers.dev.
7
Attach the Worker to your domain route
In your Worker's settings → Settings → Triggers → Add Route:
Route:  lexassist.uk/portal*
Zone:   lexassist.uk

This tells Cloudflare: any request to lexassist.uk/portal or any path underneath it gets handled by this Worker, which forwards it to Railway.

ℹ
The route lexassist.uk/portal* (with a * wildcard) catches /portal, /portal/, /portal/dashboard, /portal/api/matters, etc. — everything the app needs.

Step 4 — Update GoDaddy nameservers

This is the one change you make in GoDaddy. It hands DNS control to Cloudflare. Your domain still belongs to GoDaddy — you're just telling it to use Cloudflare's DNS servers.

⚠
Before doing this: Make sure Cloudflare has imported your existing DNS records (email MX records, any existing A records etc.) in Step 3. Once you switch nameservers, GoDaddy's DNS stops working and Cloudflare takes over.
1
Get your Cloudflare nameservers
In your Cloudflare dashboard for lexassist.uk → Overview → scroll to Nameservers. You'll see two, e.g.:
emma.ns.cloudflare.com
walt.ns.cloudflare.com
2
Log into GoDaddy
Go to godaddy.com → My Products → find lexassist.uk → click the three-dot menu → Manage DNS.
3
Change the nameservers
Scroll down to the Nameservers section → click Change → select "I'll use my own nameservers" → delete GoDaddy's default nameservers and enter Cloudflare's two nameservers → Save.
4
Wait for propagation
GoDaddy says up to 48 hours. In practice it's usually under 30 minutes. Cloudflare will email you when they detect the nameserver change has propagated.
ℹ
How to check if it's worked: Visit https://lexassist.uk/portal/ — you should see the LexAssist landing page. You can also check propagation at dnschecker.org — search for lexassist.uk and verify it shows Cloudflare's nameservers globally.

Troubleshooting

!
Portal shows blank page
The Vite base: "/portal/" config change in Step 1 is missing or the app wasn't rebuilt after the change. Re-run npm run build and redeploy.
!
Login redirects to wrong URL
The wouter <Router base="/portal"> wrapper in Step 1 is missing. After login it redirects to /dashboard instead of /portal/dashboard.
!
API calls fail (401 / 404)
The Worker route pattern needs to be lexassist.uk/portal* with a * at the end to catch API calls like /portal/api/matters. Check the route in Cloudflare Workers triggers.
?
Nameservers not propagating
Normal wait is under 1 hour but can take up to 48 hours. Check status at dnschecker.org. GoDaddy support can also force-refresh the delegation.
